# CLICKFIELD OS
## Internal Finance, Client, Project & Operations Management Platform

Build a production-ready, responsive, PWA-first web application called **Clickfield OS** for Clickfield AI.

This is an internal company management platform.

The application must combine:

1. Client Management
2. Lead / Sales Pipeline
3. Project Management
4. Agreement & Document Management
5. Income Management
6. Expense Management
7. Payment Tracking
8. Expense Approval
9. Recurring Revenue / MRR
10. Recurring Expenses
11. Financial Dashboard
12. Cash Flow
13. Project Profitability
14. Notifications
15. Audit Logs
16. User Roles & Permissions
17. Reports
18. Settings

The system must be intentionally SIMPLE.

Do NOT turn this into a complicated ERP.

Do NOT build AI features.

Do NOT add unnecessary accounting complexity.

The primary goal is:

> Give Clickfield AI one place where management can understand clients, projects, money coming in, money going out, pending payments, recurring revenue, expenses, documents, approvals and profitability.

---

# 1. PRODUCT PHILOSOPHY

The application should follow these principles:

### Simple

A person with no accounting background should understand the interface immediately.

### Fast

Pages should load quickly.

Tables should be searchable and filterable.

Avoid unnecessary animations.

### Reliable

Financial data must never silently disappear or become inconsistent.

### Traceable

Every important financial action must have an audit trail.

### Permission controlled

Employees should only see and modify information appropriate to their role.

### Mobile-first responsive

The application must work properly at:

- 360px mobile
- 390px mobile
- 430px mobile
- 768px tablet
- 1024px tablet/laptop
- 1280px desktop
- 1440px desktop
- 1920px desktop

Do not simply shrink the desktop UI.

Create proper mobile layouts.

- Authentication

- Server-side authorization
- Secure file access
- Input validation

# 20. PROJECT CLOSURE RULE

This is a critical business rule.

A project must NOT be allowed to become:

> Closed

unless mandatory closure requirements are satisfied.

At minimum:

```text
Agreement uploaded
Final deliverables completed
Final payment status recorded
Closure notes added
```

If the agreement is missing:

```text
Project cannot be closed.

Required document:
Agreement

[Upload Agreement]
```

The Close Project button must remain disabled.

Do not rely only on frontend validation.

Enforce this rule server-side.

# 49. BUSINESS RULES

Implement these rules.

### Rule 1

Closed project requires agreement.

### Rule 2

Only authorized users can approve expenses.

### Rule 3

Approved financial records cannot be silently edited.

If modification is required:

### Rule 4

Deleted financial records should normally be soft-deleted/voided.

### Rule 5

Only authorized users can see company-wide financial data.

### Rule 6

Employees should only see relevant projects/expenses according to permissions.

### Rule 7

Payment received must update outstanding balance.

### Rule 8

MRR should be calculated from active recurring revenue records.

### Rule 9

Recurring expenses should generate expected transactions.

### Rule 10

Project closure must validate all mandatory closure requirements server-side.
